# Repository roles and upstream contribution work

The libraries listed in the profile are maintained here. The repositories below are forks of separate upstream projects. Their role is a workspace for reviewing, experimenting with, and preparing upstream changes. This inventory does not assert that any particular change was merged, adopted, or released.

| Fork | Upstream | Contribution workspace focus |
|---|---|---|
| [OpenMAIC](https://github.com/ashutoshrana/OpenMAIC) | [THU-MAIC/OpenMAIC](https://github.com/THU-MAIC/OpenMAIC) | Classroom and learning-agent application integration |
| [crewAI](https://github.com/ashutoshrana/crewAI) | [crewAIInc/crewAI](https://github.com/crewAIInc/crewAI) | Agent orchestration integration |
| [haystack](https://github.com/ashutoshrana/haystack) | [deepset-ai/haystack](https://github.com/deepset-ai/haystack) | Retrieval pipeline integration |
| [haystack-integrations](https://github.com/ashutoshrana/haystack-integrations) | [deepset-ai/haystack-integrations](https://github.com/deepset-ai/haystack-integrations) | Component integration and compatibility |
| [dify](https://github.com/ashutoshrana/dify) | [langgenius/dify](https://github.com/langgenius/dify) | Application workflow integration |
| [ard-spec](https://github.com/ashutoshrana/ard-spec) | [ards-project/ard-spec](https://github.com/ards-project/ard-spec) | Specification examples and conformance testing |

For accepted work, the source of truth is the upstream pull request, final merged diff, checks, and release notes. A proposal or fork commit alone does not establish an accepted contribution. Fork maintenance should follow a concrete upstream issue or compatibility need.
